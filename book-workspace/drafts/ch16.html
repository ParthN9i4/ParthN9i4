16.1 Locality, Weight Sharing, Equivariance

Deep learning's “convolution” is cross-correlation: no kernel flip. The distinction is invisible during training, since a learned $w$ can absorb the flip, but it is not invisible when you port weights between a framework and scipy.signal.convolve2d, or when you reason about the backward pass, which really does flip.

Definition 16.1 (Convolution layer)

Given input $x \in \mathbb{R}^{C_{\text{in}}\times H\times W}$, kernel $w\in\mathbb{R}^{C_{\text{out}}\times C_{\text{in}}\times k_h\times k_w}$ and bias $b\in\mathbb{R}^{C_{\text{out}}}$, with stride $s$, zero-padding $p$ and dilation $d$, $$y[o,i,j] \;=\; b[o] \;+\; \sum_{c=0}^{C_{\text{in}}-1}\sum_{u=0}^{k_h-1}\sum_{v=0}^{k_w-1} w[o,c,u,v]\; x^{p}\!\left[c,\; s\,i + d\,u,\; s\,j + d\,v\right],$$ where $x^{p}$ is $x$ zero-padded by $p$ on each side. The layer is sparse ($y[o,i,j]$ depends on $C_{\text{in}}k_hk_w$ inputs, not all $C_{\text{in}}HW$), shared (the same $w$ is used at all $(i,j)$), and consequently has $C_{\text{out}}C_{\text{in}}k_hk_w + C_{\text{out}}$ parameters independent of $H,W$.

Theorem 16.1 (Translation equivariance)

Let $T_\delta$ shift by $\delta\in\mathbb{Z}^2$ on an unbounded input domain, and let $\mathcal{K}_w$ be the layer of Definition 16.1 with $s=1$. Then $\mathcal{K}_w(T_\delta x) = T_\delta \mathcal{K}_w(x)$ for every $\delta$. For $s>1$, $\mathcal{K}_w(T_{s\delta}x) = T_{\delta}\mathcal{K}_w(x)$, and equivariance holds only on the subgroup $s\mathbb{Z}^2$.

Proof. With $s=1$, $\mathcal{K}_w(T_\delta x)[o,i,j]=\sum_{c,u,v}w[o,c,u,v]\,x[c,i+du-\delta_1,j+dv-\delta_2] = \mathcal{K}_w(x)[o,i-\delta_1,j-\delta_2]$. For general $s$, index $i$ maps to input coordinate $si$, so a shift of the output by $1$ corresponds to a shift of the input by $s$; a shift by any $\delta\notin s\mathbb{Z}^2$ is not realizable. $\blacksquare$

Three consequences worth stating. First, equivariance is exact only in the interior: zero padding breaks it at the boundary, which is exactly how a CNN can learn absolute position from a padded input at all — a documented and often unwanted capability. Likely Second, stride, pooling, and any downsampling degrade equivariance to the subgroup $s\mathbb{Z}^2$, so a CNN with total stride $32$ is genuinely equivariant only to multiples of $32$ pixels; the rest is learned robustness, not structure. Third, convolution is equivariant to translation and to nothing else — not rotation, not scale. Those must come from data augmentation or from a different group-equivariant construction.

The prior is a constraint, and constraints cost capacity. A convolution layer is a dense layer whose weight matrix is constrained to be block-Toeplitz with $C_{\text{out}}C_{\text{in}}k_hk_w$ free entries out of $C_{\text{out}}HW \times C_{\text{in}}HW$. When the prior is right this is a variance reduction of enormous size; when it is wrong — a fully connected first layer on tabular data reshaped into a grid — it is bias you cannot train away.

16.2 Convolution Arithmetic: stride, padding, dilation

Dilation inserts $d-1$ zeros between kernel taps, so a $k\times k$ kernel at dilation $d$ has effective kernel size $k_{\text{eff}} = d(k-1)+1$ while keeping $k^2$ parameters. The output size is then the number of positions the effective window fits into the padded input: $$H_{\text{out}} = \left\lfloor \frac{H + 2p - d(k_h-1) - 1}{s}\right\rfloor + 1.$$ The floor is where the bugs live: when $s>1$ and the numerator is not divisible by $s$, the last few input rows are simply never visited, and no error is raised.

Example 16.1 (Every arithmetic case on one line)

Take $H=13$, $k=3$. Plain ($s{=}1,p{=}0,d{=}1$): $\lfloor(13-2-1)/1\rfloor+1 = 11$. Same padding ($p{=}1$): $\lfloor(15-2-1)/1\rfloor+1 = 13$. Strided ($s{=}2,p{=}1$): $\lfloor 12/2\rfloor+1=7$. Dilated ($d{=}2,p{=}2$): $k_{\text{eff}}=5$, $\lfloor(17-4-1)/1\rfloor+1=13$ — same output size as $p{=}1,d{=}1$, but each output sees $5$ input pixels instead of $3$, for the same $9$ parameters. Now the failure: $H=13$, $k=3$, $s=2$, $p=0$ gives $\lfloor 10/2\rfloor+1 = 6$, consuming inputs $0\ldots11$; row $12$ is discarded silently.

Parameter and FLOP counts follow directly from Definition 16.1. Each of the $C_{\text{out}}H_{\text{out}}W_{\text{out}}$ outputs is a dot product of length $C_{\text{in}}k_hk_w$, so $$\#\text{params} = C_{\text{out}}C_{\text{in}}k_hk_w + C_{\text{out}}, \qquad \text{MACs} = C_{\text{out}}C_{\text{in}}k_hk_w H_{\text{out}}W_{\text{out}},$$ and FLOPs $= 2\times$ MACs, counting a multiply and an add separately. Most of the vision literature reports MACs and calls them FLOPs; when a paper says ResNet-50 is “4.1 GFLOPs” it means $4.1$ G multiply-accumulates, i.e. $8.2$ GFLOPs by the convention of this book. Certain Note what does not appear: $H_{\text{out}}W_{\text{out}}$ scales the FLOPs but not the parameters, which is why early high-resolution layers are compute-heavy and cheap in memory while late $1\times1$ layers at $7\times7$ resolution are the opposite.

16.3 im2col and the Matmul Reduction

Definition 16.1 is a linear map, so it is a matrix multiply; the only question is which one. The im2col (image-to-column) construction makes the choice that keeps the weight matrix small: materialize the patches instead of the operator.

Build $C \in \mathbb{R}^{(C_{\text{in}}k_hk_w)\times(H_{\text{out}}W_{\text{out}})}$ whose column $(i,j)$ is the flattened receptive-field patch feeding output position $(i,j)$, and reshape $w$ into $W_{\text{mat}}\in\mathbb{R}^{C_{\text{out}}\times(C_{\text{in}}k_hk_w)}$. Then, per image, $$Y = W_{\text{mat}}\,C + b\mathbf{1}^\top,$$ a dense GEMM of shape $(C_{\text{out}}, C_{\text{in}}k_hk_w, H_{\text{out}}W_{\text{out}})$, whose multiply-accumulate count is exactly the MAC count above. Nothing is approximated; the reduction is an identity, and the reason it dominated CNN implementations for a decade is that it converts an awkward stencil into the single kernel every vendor has optimized to within a few percent of peak.

The cost is duplication. Each input pixel appears in as many columns as there are windows covering it — up to $k_hk_w/s^2$ — so $C$ is roughly $k_hk_w/s^2$ times the size of the input activation. For a $3\times3$, stride-$1$ layer on a $256\times56\times56$ map in fp32, the input is $3.2$ MB and $C$ is $28.9$ MB, well past any L2 cache. This is why modern kernels do implicit GEMM: they compute the im2col indices inside the tiling loop and never write $C$ to memory. The arithmetic is identical; the memory traffic is not. Chapter 30 makes this the general rule.

Common Pitfall

The inverse of im2col is not an inverse. Scattering columns back to image positions with fancy-index assignment — Xp[:, k, i, j] = cols — silently keeps only the last write when windows overlap, which is always unless $s \ge k$. You need accumulation: np.add.at(Xp, (slice(None), k, i, j), cols), or a scatter-add. The bug is nasty because it is invisible at $s=k$ (non-overlapping windows) and at $k=1$, so a unit test that only covers $1\times1$ and $2\times2$-stride-$2$ passes while every real layer is wrong. It also passes any test that checks only $\bar{w}$, since the weight gradient never touches col2im.

16.4 The Backward Pass

Once the layer is $Y = W_{\text{mat}}C$, Chapter 11's rules give the gradients in one line each: $\bar{W}_{\text{mat}} = \bar{Y}C^\top$, $\bar{C} = W_{\text{mat}}^\top \bar{Y}$, $\bar{b} = \bar{Y}\mathbf{1}$, and $\bar{x} = \mathrm{col2im}(\bar{C})$, where col2im is the adjoint of im2col — the scatter-add of the pitfall box. That is the whole implementation. The classical statement of the same fact is more informative about what the operation is.

Theorem 16.2 (Backward is a flipped convolution)

For $s=d=1$ and no padding, writing $y[o,\mathbf{p}] = \sum_{c,\mathbf{u}} w[o,c,\mathbf{u}]\,x[c,\mathbf{p}+\mathbf{u}]$ with $\mathbf{u}\in\{0,\ldots,k-1\}^2$: $$\bar{x}[c,\mathbf{q}] = \sum_{o}\sum_{\mathbf{u}} \bar{y}[o,\mathbf{q}-\mathbf{u}]\, w[o,c,\mathbf{u}], \qquad \bar{w}[o,c,\mathbf{u}] = \sum_{\mathbf{p}} \bar{y}[o,\mathbf{p}]\,x[c,\mathbf{p}+\mathbf{u}].$$ The first is a full correlation of $\bar{y}$ with the kernel $\tilde{w}[c,o,\mathbf{u}] = w[o,c,k-1-\mathbf{u}]$: spatially flipped and with input/output channel axes transposed, applied with padding $k-1$. The second is a correlation of $x$ with $\bar{y}$, i.e. a convolution in which $\bar y$ plays the role of the kernel. With stride $s$, $\bar{x}$ is obtained by first dilating $\bar y$ — inserting $s-1$ zeros between its entries — and then applying the same full correlation; with dilation $d$, the flipped kernel is applied at dilation $d$.

Proof. $\bar{x}[c,\mathbf{q}] = \sum_{o,\mathbf{p}} \bar{y}[o,\mathbf{p}]\,\partial y[o,\mathbf{p}]/\partial x[c,\mathbf{q}]$, and the partial is $w[o,c,\mathbf{q}-\mathbf{p}]$ when $\mathbf{q}-\mathbf{p}\in\{0,\ldots,k-1\}^2$ and zero otherwise. Substituting $\mathbf{u}=\mathbf{q}-\mathbf{p}$ gives the stated sum; reindexing $\mathbf{u}\mapsto k-1-\mathbf{u}$ turns the convolution into a correlation with the flipped kernel, and its support requires zero-padding $\bar y$ by $k-1$. For $\bar{w}$, $\partial y[o,\mathbf{p}]/\partial w[o,c,\mathbf{u}] = x[c,\mathbf{p}+\mathbf{u}]$ and the sum over $\mathbf{p}$ is the parameter-sharing sum — every spatial position contributes to the same weight, which is precisely why weight sharing turns one gradient into an average over $H_{\text{out}}W_{\text{out}}$ locations and gives convolutions their low gradient variance. For stride $s$, only $\mathbf{p}$ with $s\mathbf{p}+\mathbf{u}=\mathbf{q}$ contribute, and the set of such $\mathbf{p}$ is exactly what zero-insertion into $\bar y$ realizes. $\blacksquare$

Two things fall out. The stride-$s$ backward — zero-insert, then full-correlate — is the definition of transposed convolution, so a deconvolution layer in a generator or segmentation decoder is literally the gradient operator of a strided convolution, and its checkerboard artifacts are the zero-insertion pattern showing through when $k$ is not divisible by $s$. Certain And the two gradients are structurally different operations: $\bar x$ is a convolution with $C_{\text{out}}$ as the contracted axis, $\bar w$ is a convolution with the batch-and-spatial axes contracted. That is why a backward pass costs about twice a forward pass, not once.

16.5 Pooling, Downsampling, and Receptive Fields

The receptive field of a unit is the set of input pixels that can change its value. It is the architectural quantity that matters most and the one most often left uncomputed.

Theorem 16.3 (Receptive-field recursion)

For a stack of layers $l=1,\ldots,L$ with kernel $k_l$, stride $s_l$, dilation $d_l$, define the jump $j_l$ (input pixels per unit step at layer $l$) and receptive field $r_l$ by $j_0=r_0=1$ and $$j_l = j_{l-1}s_l, \qquad r_l = r_{l-1} + (k_l-1)\,d_l\,j_{l-1}.$$ Equivalently $j_L = \prod_l s_l$ and $r_L = 1 + \sum_{l=1}^{L}(k_l-1)\,d_l\prod_{m<l}s_m$. Padding does not affect $r_L$; it affects only which outputs have their window fully inside the image.

Proof. By induction. A unit at layer $l$ reads $k_l$ units of layer $l-1$ whose indices are spaced $d_l$ apart. Consecutive layer-$(l-1)$ units have receptive fields of extent $r_{l-1}$ offset by $j_{l-1}$ input pixels, so units spaced $d_l$ apart are offset by $d_lj_{l-1}$, and the union of $k_l$ such intervals spans $r_{l-1} + (k_l-1)d_lj_{l-1}$ — contiguously, since $d_lj_{l-1}\le r_{l-1}$ in any stack where the dilation does not exceed the current receptive field. The jump relation is immediate: moving one step at layer $l$ moves $s_l$ steps at layer $l-1$. $\blacksquare$

The recursion explains the whole shape of CNN design. Stacking $L$ layers of $3\times3$ at stride $1$ gives $r_L = 2L+1$: linear growth, so reaching a $224$-pixel field needs $112$ layers. Downsampling makes growth geometric — each stride-$2$ layer doubles $j$, so subsequent kernels advance $r$ twice as fast — which is why every classical CNN is a sequence of stride-$1$ blocks punctuated by stride-$2$ transitions, and why VGG's substitution of three $3\times3$ layers for one $7\times7$ is favourable: same $r=7$, $3(9C^2)=27C^2$ parameters instead of $49C^2$, and two extra nonlinearities. Dilation buys the same growth with no downsampling at all, which is why segmentation networks use dilated stacks: an exponential schedule $d=1,2,4,8$ of $3\times3$ layers gives $r = 1+2(1+2+4+8) = 31$ at full resolution.

The theoretical receptive field is an upper bound on influence, not a description of it. Under random initialization the gradient magnitude at the edge of the window is vanishingly small: the number of distinct paths from an input pixel to an output unit is binomially distributed over the window, so the effective receptive field is approximately Gaussian and grows as $O(\sqrt{L})$ rather than $O(L)$. Likely The practical consequence is that a network whose nominal receptive field just covers the object usually behaves as though it does not, and architectures overshoot deliberately.

Max-pooling versus strided convolution is the one genuinely settled part of this section: strided and average-pooled downsampling dominate in modern designs, and max-pooling survives mainly in the first stem of ResNet-style nets. Likely Both are aliasing operators — they subsample without a low-pass filter, so shifting the input by one pixel can change the output substantially, and anti-aliased (blur-pool) downsampling measurably restores shift-consistency at a small FLOP cost. Global average pooling at the head is a different matter: it removes the spatial index entirely, making the classifier translation-invariant rather than equivariant, and eliminates the parameter blowup of VGG's $25088\times4096$ first dense layer ($102.8$ M parameters, three quarters of the network).

16.6.1 Why residuals work: two accounts

A residual block computes $a^{(l)} = a^{(l-1)} + F_l(a^{(l-1)})$. Differentiating, with $J_l = \partial F_l/\partial a^{(l-1)}$, $$\frac{\partial a^{(L)}}{\partial a^{(l)}} = \prod_{m=l+1}^{L}\left(I + J_m\right).$$ Account one (identity path). The product contains the term $I$ exactly, so the gradient reaching layer $l$ is the gradient at layer $L$ plus corrections. In a plain network the corresponding product is $\prod_m J_m$, whose singular values are products of $L-l$ factors and therefore vanish or explode exponentially unless every $J_m$ is held near-isometric — the pathology Chapter 12 quantifies and Chapter 17 meets again in time rather than depth. Residuals make degeneracy impossible by construction: the identity term cannot be scaled away by initialization. Zero-initializing the last normalization scale in each block starts the network as the exact identity, and that trick alone stabilizes very deep training. Certain

Account two (ensemble of paths). Expanding the product gives $2^{L-l}$ terms, one for each subset $S\subseteq\{l+1,\ldots,L\}$: $\sum_{S} \prod_{m\in S}J_m$ (ordered). Each term is a distinct computational path through the network that either enters or skips each block, so an $L$-block ResNet is a combinatorial ensemble of $2^L$ paths of every depth from $0$ to $L$. Path lengths are binomially distributed, and the gradient carried by a path decays roughly exponentially in its length, so the paths that contribute are the short ones: measured on a $54$-block ResNet, essentially all gradient magnitude comes from paths of length under about $20$. This account also predicts — correctly — that deleting a single residual block from a trained ResNet barely changes accuracy, while deleting a layer from VGG destroys it. Likely

The two accounts are not rivals; they are the same expansion read term-by-term versus as a whole. Where they disagree is on what “depth” means: the identity-path account says a $152$-layer ResNet is $152$ layers deep and optimizable; the ensemble account says its effective depth is closer to $20$ and the rest is width in disguise. Contested The evidence that would settle it is already partly in — lesion studies and path-length measurements favour the ensemble reading, while the fact that very deep ResNets still beat wide shallow ones at matched parameters favours real depth. My position: both are true, because effective depth grows like $\sqrt{L}$, so $152$ layers do buy depth, just not $152$ layers of it.

EfficientNet's contribution is orthogonal and quantitative: given a compute budget multiplier $\phi$, scale depth, width and resolution jointly as $d^\phi$, $w^\phi$, $r^\phi$ with $d\,w^2r^2 \approx 2$, rather than any one alone. The constraint is just the FLOP arithmetic of Section 16.2 — FLOPs are linear in depth and quadratic in both width and resolution — and the empirical claim is that the optimal allocation is balanced. Chapter 24 develops the same argument for language models, where the axes are parameters and data.

The prior still buys something, and the place to look is the small-data regime. ViTs trained on ImageNet-1k alone underperform comparable ConvNets and need either large-scale pretraining (JFT-300M) or heavy augmentation plus distillation to close the gap, because a Transformer must learn locality from data that a convolution asserts for free. Contested The counter-position — that this is an optimization artifact that better recipes keep eroding, and that hybrid stems already remove most of it — has been gaining ground. What would settle it is a matched-compute sweep across dataset sizes with recipes independently tuned per architecture; the prediction is a crossover, with convolution ahead below roughly $10^7$ images and the gap closing above.

16.8 Depthwise-Separable Convolutions

Factor a $k\times k$, $C\to C$ convolution into a depthwise stage (groups $=C$, each channel convolved by its own $k\times k$ kernel, no channel mixing) and a pointwise $1\times1$ stage (channel mixing, no spatial extent). The cost ratio against the dense layer is $$\frac{C k^2 HW + C^2HW}{C^2k^2HW} = \frac{1}{C} + \frac{1}{k^2},$$ independent of resolution. At $C=256$, $k=3$ this is $1/256 + 1/9 = 0.115$: an $8.7\times$ reduction in both MACs and parameters, which is the entire basis of MobileNet, Xception and the ConvNeXt block.

The trap is that FLOPs are not time. The depthwise stage does $k^2 = 9$ MACs per loaded value against the dense layer's $C k^2 = 2304$, so its arithmetic intensity is two orders of magnitude lower and it is firmly memory-bandwidth-bound on any accelerator. A depthwise-separable network with $8.7\times$ fewer FLOPs routinely runs only $2$–$3\times$ faster on a GPU. Verify Chapter 30 gives the roofline model that predicts exactly this, and it is the same reason a $7\times7$ depthwise kernel in ConvNeXt is nearly free: the layer was bandwidth-bound at $3\times3$ and stays bandwidth-bound at $7\times7$.

Artifact 16.1 — Conv2d forward and backward from scratch

Pure-NumPy Conv2d via im2col with full stride/padding/dilation/groups support, plus the col2im adjoint. Forward is checked against torch.nn.functional.conv2d and both gradients against torch.autograd over six configurations including grouped, depthwise, and anisotropic stride/pad/dilation. It then measures the receptive field of a seven-layer stack by seeding one output unit's gradient and finding which input pixels come back nonzero, and compares that to Theorem 16.3.

"""Chapter 16 artifact: Conv2d forward + backward from scratch via im2col.

Core is pure NumPy. torch is used only as a cross-check and is import-guarded.
Everything is verified: forward against torch.nn.Conv2d, and BOTH gradients
(input and weight) against torch.autograd, over random stride/padding/dilation/
groups configurations. Finally we measure the receptive field of a deep stack
empirically -- which input pixels carry nonzero gradient -- and compare it to
the analytic recursion r_l = r_{l-1} + (k_l - 1) * d_l * j_{l-1}.
"""
import numpy as np

try:
    import torch
except ImportError:  # pragma: no cover
    torch = None


# ----------------------------------------------------------------------------
# im2col: the index arithmetic that turns a sliding window into a matmul.
# ----------------------------------------------------------------------------
def _im2col_indices(Cin, H, W, KH, KW, stride, pad, dil):
    """Return (k, i, j) index arrays selecting patches out of the PADDED input.

    Shapes: each is (Cin*KH*KW, Hout*Wout) after broadcasting, so that
    Xpad[:, k, i, j] is (B, Cin*KH*KW, Hout*Wout) -- the column matrix.
    """
    sh, sw = stride
    ph, pw = pad
    dh, dw = dil
    Hout = (H + 2 * ph - dh * (KH - 1) - 1) // sh + 1
    Wout = (W + 2 * pw - dw * (KW - 1) - 1) // sw + 1
    # offsets within one kernel window (dilated)
    i0 = np.repeat(np.arange(KH), KW) * dh            # (KH*KW,)
    i0 = np.tile(i0, Cin)                             # (Cin*KH*KW,)
    j0 = np.tile(np.arange(KW) * dw, KH * Cin)
    # top-left corner of each output position (strided)
    i1 = sh * np.repeat(np.arange(Hout), Wout)        # (Hout*Wout,)
    j1 = sw * np.tile(np.arange(Wout), Hout)
    i = i0.reshape(-1, 1) + i1.reshape(1, -1)
    j = j0.reshape(-1, 1) + j1.reshape(1, -1)
    k = np.repeat(np.arange(Cin), KH * KW).reshape(-1, 1)
    return k, i, j, Hout, Wout


def im2col(X, KH, KW, stride, pad, dil):
    """X: (B, Cin, H, W) -> cols: (B, Cin*KH*KW, Hout*Wout)."""
    B, Cin, H, W = X.shape
    ph, pw = pad
    Xp = np.pad(X, ((0, 0), (0, 0), (ph, ph), (pw, pw)))
    k, i, j, Hout, Wout = _im2col_indices(Cin, H, W, KH, KW, stride, pad, dil)
    return Xp[:, k, i, j], Hout, Wout


def col2im(cols, Xshape, KH, KW, stride, pad, dil):
    """Adjoint of im2col: scatter-add columns back into an input-shaped array."""
    B, Cin, H, W = Xshape
    ph, pw = pad
    Xp = np.zeros((B, Cin, H + 2 * ph, W + 2 * pw), dtype=cols.dtype)
    k, i, j, _, _ = _im2col_indices(Cin, H, W, KH, KW, stride, pad, dil)
    # np.add.at accumulates on repeated indices -- overlapping windows demand it.
    np.add.at(Xp, (slice(None), k, i, j), cols)
    return Xp[:, :, ph:H + ph, pw:W + pw]


# ----------------------------------------------------------------------------
# Conv2d forward / backward, grouped.
# ----------------------------------------------------------------------------
def conv2d_forward(X, Wt, b, stride=(1, 1), pad=(0, 0), dil=(1, 1), groups=1):
    """X:(B,Cin,H,W)  Wt:(Cout,Cin/g,KH,KW)  b:(Cout,) -> Y:(B,Cout,Hout,Wout)."""
    B, Cin, H, W = X.shape
    Cout, Cing, KH, KW = Wt.shape
    assert Cin == Cing * groups and Cout % groups == 0
    Og = Cout // groups
    outs, caches = [], []
    for g in range(groups):
        Xg = X[:, g * Cing:(g + 1) * Cing]
        cols, Hout, Wout = im2col(Xg, KH, KW, stride, pad, dil)   # (B, Cing*KH*KW, P)
        Wg = Wt[g * Og:(g + 1) * Og].reshape(Og, -1)              # (Og, Cing*KH*KW)
        Yg = np.einsum('ok,bkp->bop', Wg, cols)                   # (B, Og, P)
        outs.append(Yg.reshape(B, Og, Hout, Wout))
        caches.append(cols)
    Y = np.concatenate(outs, axis=1) + b.reshape(1, -1, 1, 1)
    return Y, (caches, X.shape, Wt, stride, pad, dil, groups)


def conv2d_backward(dY, cache):
    """Returns dX, dW, db. dW is a correlation of X with dY; dX is col2im of W^T dY."""
    caches, Xshape, Wt, stride, pad, dil, groups = cache
    B, Cin, H, W = Xshape
    Cout, Cing, KH, KW = Wt.shape
    Og = Cout // groups
    db = dY.sum(axis=(0, 2, 3))
    dX_parts, dW_parts = [], []
    for g in range(groups):
        cols = caches[g]
        dYg = dY[:, g * Og:(g + 1) * Og].reshape(B, Og, -1)        # (B, Og, P)
        # weight gradient: sum over batch and spatial positions
        dWg = np.einsum('bop,bkp->ok', dYg, cols)                  # (Og, Cing*KH*KW)
        dW_parts.append(dWg.reshape(Og, Cing, KH, KW))
        # input gradient: transpose of the matmul, then scatter back (col2im)
        Wg = Wt[g * Og:(g + 1) * Og].reshape(Og, -1)
        dcols = np.einsum('ok,bop->bkp', Wg, dYg)                  # (B, Cing*KH*KW, P)
        dX_parts.append(col2im(dcols, (B, Cing, H, W), KH, KW, stride, pad, dil))
    return np.concatenate(dX_parts, axis=1), np.concatenate(dW_parts, axis=0), db



def conv_flops_params(Cin, Cout, KH, KW, Hout, Wout, groups=1, bias=True):
    """Analytic counts. FLOPs counted as multiply-adds x2, per single image."""
    params = Cout * (Cin // groups) * KH * KW + (Cout if bias else 0)
    macs = Cout * (Cin // groups) * KH * KW * Hout * Wout
    return params, 2 * macs


def receptive_field(layers):
    """layers: list of (k, s, d). Returns (r, jump) after the whole stack."""
    r, j = 1, 1
    for (k, s, d) in layers:
        r = r + (k - 1) * d * j
        j = j * s
    return r, j

def check_config(cfg, rng):
    B, Cin, Cout, H, W, KH, KW, st, pd, dl, g = cfg
    X = rng.standard_normal((B, Cin, H, W))
    Wt = rng.standard_normal((Cout, Cin // g, KH, KW)) * 0.3
    b = rng.standard_normal(Cout) * 0.1
    Y, cache = conv2d_forward(X, Wt, b, st, pd, dl, g)
    dY = rng.standard_normal(Y.shape)
    dX, dW, db = conv2d_backward(dY, cache)
    if torch is None:
        return None
    tX = torch.tensor(X, requires_grad=True)
    tW = torch.tensor(Wt, requires_grad=True)
    tb = torch.tensor(b, requires_grad=True)
    tY = torch.nn.functional.conv2d(tX, tW, tb, stride=st, padding=pd,
                                    dilation=dl, groups=g)
    tY.backward(torch.tensor(dY))
    ef = np.abs(Y - tY.detach().numpy()).max()
    ex = np.abs(dX - tX.grad.numpy()).max()
    ew = np.abs(dW - tW.grad.numpy()).max()
    eb = np.abs(db - tb.grad.numpy()).max()
    return Y.shape, ef, ex, ew, eb

Under Encryption

A convolution is a linear map, so it is CKKS-friendly in principle — but the packing is the whole problem. Under SIMD packing an image occupies the slots of one ciphertext, and each output slot needs a different subset of input slots, so the sliding window cannot be expressed by slot-wise multiplication alone. The standard evaluation costs one rotation per kernel position: $k^2$ rotations and $k^2$ plaintext multiplies per output channel, with rotations dominating because each requires a key-switch, the expensive primitive — typically an order of magnitude costlier than a slot-wise multiply. Encrypted CNN inference therefore budgets rotations, not multiplications, which inverts the plaintext accounting of Section 16.2 entirely: a $1\times1$ pointwise convolution is nearly free spatially but expensive across channels, while a $7\times7$ depthwise kernel costs $49$ rotations and no channel mixing at all. The three standard levers are to fold the whole convolution into a single matrix–vector product (paying diagonal-packing rotations once, amortized by baby-step/giant-step to $O(\sqrt{n})$), to choose a packing whose slot stride aligns with the window stride so that consecutive windows are related by a single rotation, or to use depthwise separability precisely to cut the rotation count. Multiplicative depth is the easy part here: one convolution is depth $1$, so a $50$-layer ConvNet's depth budget is set by its activations, not its convolutions. Chapter 41 works this arithmetic out for attention, where the same tension appears in a harder form.

Key Takeaways
  • A convolution is a dense layer whose matrix is constrained to be block-Toeplitz; im2col makes the reduction to GEMM exact, at the price of a $k_hk_w/s^2$ activation blowup that implicit-GEMM kernels avoid by never materializing it. Certain
  • The backward pass is a full correlation of $\bar y$ with the spatially flipped, channel-transposed kernel (with zero-insertion for stride), and $\bar w$ is a correlation of $x$ with $\bar y$ — the same identity that makes transposed convolution the gradient of strided convolution. Certain
  • Receptive field follows $r_l = r_{l-1} + (k_l-1)d_lj_{l-1}$, $j_l = j_{l-1}s_l$: linear in depth without downsampling, geometric with it, and the effective field is Gaussian and grows only as $O(\sqrt{L})$. Likely
  • Residual connections put an exact $I$ in $\prod_m (I+J_m)$, which both forbids multiplicative gradient degeneracy and expands into $2^{L-l}$ paths dominated by short ones; the two readings disagree only about what “effective depth” means. Contested
  • ConvNeXt's ladder attributes $2.7$ of the $5.2$-point ResNet-50-to-Swin-T gap to the training recipe with the architecture untouched; the convolutional prior's remaining advantage is concentrated in the small-data regime. Likely
